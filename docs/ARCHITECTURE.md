# Architecture

Gita Verse is a static website on Vercel that talks directly to a Supabase project. There is no build step and no application server of our own: the browser calls Supabase (database API, Auth and edge functions), and the edge functions call the paid providers (Gemini, ElevenLabs, Razorpay, MSG91).

```
Browser (index.html + app.js)
  ├── Supabase Auth ........ email/password, Google, mobile OTP (SMS via send-sms → MSG91)
  ├── Supabase REST/RPC .... verses, stored translations, visit/event logging
  ├── Edge functions ....... ask-krishna (Gemini), tts-krishna (Gemini + ElevenLabs),
  │                          get-my-access, create-payment-link (Razorpay)
  ├── /api/geo (Vercel) .... visitor city for the dashboard
  └── Meta Pixel ........... ad measurement (see TRACKING.md)
Razorpay ──webhook──> razorpay-webhook ──> user_accounts (unlocks Annual Access)
```

## Frontend

| File | Role |
| --- | --- |
| `index.html` | All screens, inline styles, the Meta Pixel snippet. |
| `app.js` | All behaviour (~1,250 lines, plain browser JavaScript, no framework). |
| `languages.js` | The 74 supported languages (`GITA_LANGUAGES`). Must match `supabase/functions/_shared/languages.ts`; a unit test checks this. |
| `connected.css` | Extra styles for the main app. |
| `admin.html` | Owner dashboard, self-contained (its own login, separate from the main site's). |
| `privacy.html`, `terms.html`, `refund.html`, `contact.html`, `legal.css` | Policy pages, generated by `tools/build_legal_pages.py`. Edit the script, not the HTML. |
| `api/geo.js` | Vercel function returning `{country, region, city}` from Vercel's edge headers. |
| `vercel.json` | Redirects old `*.vercel.app` hostnames to gitaverse.co.in. |
| `.vercelignore` | Keeps backend code, tests and tools off the public site. |

### Screens

The app is a single page. `showScreen(id)` switches between `<section class="screen">` elements: `home`, `ask` (Ask Krishna chat), `explore`, `chapter`, `detail` (one verse), `topicScreen`, `authScreen` (sign-in) and `accountScreen`.

## Backend (Supabase project `bkwvuckznpaawmqrjjgk`, Mumbai)

### Edge functions (`supabase/functions/`)

JWT verification at the gateway is **off** for every function (see `supabase/config.toml`); each function checks the caller itself.

| Function | Caller and check | What it does |
| --- | --- | --- |
| `ask-krishna` | Signed-in user | Retrieves relevant verses (curated topics + `search_gita`), asks Gemini for a reply that cites only those verses, validates every citation. Without Annual Access it claims the one free question (`claim_free_question`) and refunds it if no answer comes back. |
| `tts-krishna` | Signed-in user with Annual Access | `operation: "translate"` returns a translated meaning (stored translation first, Gemini otherwise). Otherwise narrates text with ElevenLabs (Sanskrit chant voice for verses, v3 voice for meanings). |
| `get-my-access` | Signed-in user | Plan, expiry, `access_active`, `free_question_available`. |
| `create-payment-link` | Signed-in user | Creates a ₹1,000 Razorpay payment link (expires in 1 hour) that returns to `/?payment=success`. |
| `razorpay-webhook` | Razorpay (HMAC signature) | On `payment_link.paid` for exactly ₹1,000, unlocks one year (stacked on top of any remaining access). Idempotent. |
| `admin-stats` | Pinned admin email **and** user id | Dashboard data from the `admin_stats` SQL function; excludes the owner's test accounts from funnel counts. |
| `translation-worker` | Token from Vault (`x-worker-token`) | Pre-translates verse text into every language in the background. |
| `send-sms` | Supabase Auth "Send SMS" hook (Standard Webhooks signature) | Delivers the OTP through MSG91's DLT template. Indian numbers only. |
| `raga-music`, `gemini-health`, `razorpay-health` | – | Retired stubs (404/410). |

Shared code lives in `supabase/functions/_shared/`: `server.ts` (price `ANNUAL_PRICE_PAISE`, Gemini model and URL, server-key lookup, `adminClient()`) and `languages.ts`.

### Database

| Table | Purpose | Who can read |
| --- | --- | --- |
| `gita_chapters`, `gita_verses`, `verse_topics` | The Gita text, meanings, topic tags | Anyone (see note below) |
| `user_accounts` | One row per user: plan, payment, access expiry, free question used, sign-up source | The user's own row; writes are server-only |
| `payment_transactions` | Razorpay links and payments | The user's own rows; writes are server-only |
| `translation_sources`, `text_translations` | Verse-text pieces (keyed by SHA-256 of the English) and their translations | Translations: signed-in users |
| `translation_leases` | Which languages the worker is currently translating | Server only |
| `site_visits`, `site_events` | First-party analytics (see TRACKING.md) | Server only (written through `log_visit` / `log_event`) |
| `bookmarks`, `reading_progress`, `user_preferences`, `chat_threads`, `chat_messages` | From the earlier Expo app; unused by the website | The user's own rows |

**Access rule for verses:** the database lets anyone read verse text. The paywall on verse pages is enforced in the app (`hasLifetimeAccess()`), not by the database. This was a deliberate product decision; don't lock it down in the database without agreement.

SQL functions called from the site or functions: `get_daily_verse`, `search_gita`, `log_visit`, `log_event`, `set_my_attribution`, `claim_free_question` / `refund_free_question` (server only), `admin_stats` (server only), `next_translation_batch`, `claim_translation_languages`, `translation_missing`, `translation_worker_token_ok`.

A new auth user gets a `user_accounts` row automatically (trigger `on_auth_user_created_account`).

## Key flows

**Free question → sign-up.** A visitor types a question; if they aren't signed in it is saved (`savePendingQuestion`) and they go to sign-in. After sign-in (`afterSignIn`) the question is sent, `ask-krishna` claims the free question, and the answer appears.

**Sign-in methods.** Mobile OTP (first on the screen), email/password, Google. Inside Instagram/Facebook/Messenger/Threads, Google is blocked by Google itself, so the app offers mobile/email first and, on Android, an "Open in Chrome" hand-off that carries the visitor id, `fbclid` and UTM tags.

**Payment.** `startLifetimePurchase` → `create-payment-link` → Razorpay page → Razorpay calls `razorpay-webhook` (unlocks access) and returns the buyer to `/?payment=success` → `handlePaymentReturn` polls `get-my-access` until access is active, then fires Meta `Purchase` once.

**Meanings in other languages.** Each language's stored translations are loaded once (`loadStoredTranslations`); anything missing is translated through `tts-krishna` and saved if it is a known piece. `translation-worker` fills the table ahead of time.

**Narration.** Text is split at sentence ends into a short first clip (≤ 220 characters) and larger later clips, each generated while the previous one plays, so audio starts in about 2 seconds.
